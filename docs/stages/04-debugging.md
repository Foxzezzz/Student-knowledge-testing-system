# Этап 4. Отладка модулей

## Исходное состояние

Этап начат на чистой `main` с коммита `4502288`; создана `stage/04-debugging`. Две пограничные неисправности были специально оставлены в учебной реализации этапа 3 для упражнения, а не представлены как случайные производственные инциденты. В `96ba11e` добавлены воспроизводящие тесты. Среда: Linux, .NET SDK 9.0.320.

## Случай 1. Пустой вариант ответа

1. **Симптом:** модель вопроса допускает пустой, пробельный или `null`-вариант; студенту может отображаться непонятный выбор.
2. **Версия:** `4502288`, тесты в `96ba11e`.
3. **Условия:** создать `Question` с двумя вариантами, где один - `""`, `"   "` или `null`.
4. **Гипотезы:** (а) проверяется только число вариантов; (б) варианты становятся пустыми после копирования при передаче в сеанс.
5. **Диагностика:** параметризованный xUnit-тест, стек ошибки и просмотр конструктора модели.
6. **Наблюдение:** три проверки сообщили `Assert.Throws() Failure: No exception was thrown`; конструктор проверял длину массива, но не содержимое элементов. Подтверждена гипотеза (а).
7. **Исправление:** `36f1c1f` добавляет `string.IsNullOrWhiteSpace` для вариантов.
8. **Регрессия:** `Question_RejectsBlankAnswerOption` покрывает все три значения.
9. **Повтор:** сборка успешна; после первого исправления тесты: 11 успешно и 1 ошибка из-за ещё не исправленного случая 2. После обоих исправлений - 12 успешно.
10. **Вывод:** внешне проблема проявлялась пустым выбором, но возникала ещё на этапе создания модели.

## Случай 2. Повтор идентификатора вопроса

1. **Симптом:** сеанс принимает два разных вопроса с одинаковым идентификатором; диагностические события становятся неоднозначными.
2. **Версия:** `4502288`, тест в `96ba11e`.
3. **Условия:** передать через тестовый `IQuestionBank` вопросы с идентификаторами `q1` и `Q1`; по принятому правилу регистр не различается.
4. **Гипотезы:** (а) банк возвращает один вопрос дважды; (б) сеанс не проверяет уникальность идентификаторов.
5. **Диагностика:** xUnit-тест с подставным банком и просмотр конструктора `TestSession`.
6. **Наблюдение:** тест получил `Assert.Throws() Failure: No exception was thrown`; подставной банк содержит два разных вопроса, а конструктор проверял только пустой набор и `null`. Подтверждена гипотеза (б).
7. **Исправление:** `b43a934` проверяет уникальность с `StringComparer.OrdinalIgnoreCase` до начала попытки.
8. **Регрессия:** `Session_RejectsDuplicateQuestionIds`.
9. **Повтор:** после исправления `dotnet build` - 0 ошибок и предупреждений, `dotnet test` - 12 успешно, 0 ошибок.
10. **Вывод:** неоднозначность журнала вызвана не записью `Trace`, а допуском неуникальных идентификаторов на входе сеанса.

## Итог

Обе специально подготовленные неисправности воспроизведены и исправлены отдельными коммитами; контракты обновлены. Ручной запуск интерфейса на Windows не выполнялся. При изменении модели вопросов или источника банка регрессионные тесты нужно повторить.
