# Этап 3. Разработка и интеграция модулей

## Исходное состояние и ветви

В начале рабочее дерево `main` было чистым, последний коммит `ac3909d`; создана `stage/03-integration`. Индивидуальная работа моделировалась ветками `feature/03-question-bank` и `feature/03-test-session`. Вторая ветка создана после объединения первой, чтобы использовать определённый на этапе 1 интерфейс банка; это не два настоящих участника команды.

## Поток данных

```text
Окно WPF → TestSession → IQuestionBank.GetQuestions() → DemoQuestionBank
Пользователь → выбор ответа → SubmitAnswer(index) → прогресс
После последнего ответа → GetResult() → правильные / всего / процент → окно
```

Банк отвечает за вопросы, сеанс - за прохождение и подсчёт, окно - за выбор и показ. `Trace` фиксирует начало теста, идентификатор вопроса, прогресс и признак правильности; имена и персональные данные не используются. Для просмотра нужен listener, например отладчик.

## Интеграция и ограничения

Контракт `IQuestionBank` зафиксирован до написания модулей. Для сборки WPF из Linux включён `EnableWindowsTargeting`; это решает сборку, но не запуск окна. Вопрос и список вопросов копируются, чтобы изменение исходных коллекций не меняло уже начатую попытку. Успешное прохождение настоящего банка и неверный индекс проверены интеграционными тестами. Для учебной отладки на следующем этапе оставлены две специально подготовленные граничные неисправности: допускаются пустой вариант ответа и повторный идентификатор вопроса в наборе.

## Проверки

В Linux с SDK 9.0.320 `dotnet build` завершился без ошибок и предупреждений; `dotnet test` - 8 успешно, 0 ошибок. Проверены правильный и неправильный ответы, выход за границы, ранний результат, ответ после завершения, некорректный текст вопроса и взаимодействие с банком. Само WPF-окно вручную на Windows не запускалось: это остаётся отдельной проверкой.

Вывод: модули соединены и основные сценарии работают в автоматических тестах. Данные и результаты хранятся в памяти; версия не предназначена для защищённого экзамена.
